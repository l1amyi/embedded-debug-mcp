# docs/reference/ —— 从已安装工具提取的事实数据

本目录的文件由 `npm run docs:sync` **自动生成**，请勿手工编辑。

## 为什么这些可以提交

内容全部是**已安装的 J-Link 可执行文件自己输出的简短事实数据**——版本号、命令枚举、复位策略枚举。性质等同于 `gcc --help` 的输出，属于事实性接口描述，不包含 SEGGER 用户手册的正文。相比之下 `docs/vendor/` 里的 PDF 是 SEGGER 的版权文档，由 `.gitignore` 排除，原因见 `../README.md`。

## 文件

| 文件 | 来源命令 | 用途 |
| --- | --- | --- |
| `jlink-version.txt` | `f` | 版本、固件日期、授权。判断行为差异时先看这里。 |
| `jlink-cli-surface.txt` | `?` | **逐命令语法的唯一权威**。7.52a 的手册正文里没有逐命令参考（见下）。 |
| `jlink-reset-types.txt` | `RSetType`（无参数） | 本机支持的 13 种复位策略及其含义。 |
| `vendor-manifest.md` | — | 已复制厂商文件的来源、大小、SHA-256。 |

## 为什么 `?` 的输出是权威

已安装的 J-Link 是 **7.52a**，它的用户手册（UM08001，标注 7.50）**正文中并不包含逐命令参考**——第 3.2 节只讲了命令行参数和 Command File 用法。逐命令语法只存在于：

1. `JLink.exe` 的 `?` 输出（即本目录的 `jlink-cli-surface.txt`），
2. 更新版本的手册或在线知识库。

**注意：7.52a 的 `? <命令>` 会忽略参数，只输出完整列表**，不能用它查询单条命令。

在线 SEGGER 知识库描述的是**最新版**，已确认与本机存在多处不符（`loadfile` 支持的扩展名、`RSetType` 的类型数量等）。因此检索顺序应当是：**本目录 → `docs/vendor/` 手册 → 在线知识库**，并以实测为准。
